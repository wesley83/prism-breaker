Source findings: public/app.js binds setupPaddleInput only to #game-canvas. style.css applies touch-action:none only to the canvas. Root/body scroll containment and stage 100dvh depend on game-focus. display.js derives this class from active view plus API fullscreen/phoneFocus, and clears phoneFocus when API fullscreen exits. Fullscreen requests are opportunistic, so they are not a sufficient ownership contract for gameplay gestures. pointer-input.js clears ownership on window resize and ignores subsequent touch movement without a fresh pointerdown. app.js also cancels the gesture on stage ResizeObserver changes. These are concrete source risks, not proof of the exact recorded trigger.
Host boundary: Video address appears as yak-draw-9549.onpagelove.com, different from the previously published sane-guild-8399 host. Public read of the observed host returned HTTP502 with Unknown host; web lookup also failed. Therefore current source cannot be asserted to match that recording's runtime. No host was modified.
Recommendations: (1) Preferred baseline: explicit active-gameplay scroll lock and fixed viewport shell independent of fullscreen; touch-action protection on the complete steering surface, with interactive controls/dialogs correctly excluded; eliminate horizontal overflow and keep menus/dialog text scrollable. (2) Optional thumb steering strip below the board, using relative drag and robust capture to reduce obstruction. (3) Optional left/right controls for players who prefer buttons, with opposing/multiple touch ownership handled. In all cases stabilize viewport/canvas resizing and distinguish benign browser chrome resize from orientation/focus cancellation; pause or clearly recover when active steering is interrupted. Keep pinch/text zoom available in non-gameplay interfaces rather than blanket user-scalable=no. Fullscreen alone or a global preventDefault listener is not a complete fix.
Validation proposed: Genuine mobile touch drags beginning on canvas, lower margin, HUD and controls; vertical/diagonal swipes; multiple contacts; browser-toolbar show/hide; denied/fullscreen exit; orientation changes and resumed/ready states. Assert fixed page offset and correct steering/capture while allowing modal scroll and preserving Pause/share controls. Add event-path regressions plus real-device acceptance; synthetic pointer dispatch alone does not exercise native scrolling.
Reference: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action documents gesture arbitration at initial contact and pointer cancellation when the browser takes over; changes after gesture start do not fix the current gesture. https://developer.mozilla.org/en-US/docs/Web/API/Element/pointercancel_event describes panning/zooming and orientation cancellation.
