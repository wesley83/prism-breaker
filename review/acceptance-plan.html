Use disposable test installations for destructive storage tests. Sending a share requires the human tester to choose and authorize its destination. Never record credentials or private received-message content in Git.

Android installation and fullscreen

Android phone · Not run

Use a disposable test installation. Open the deployed game online; wait for Ready to play offline; install it. Close every game tab and launch from the installed icon. Rotate portrait/landscape and use the fullscreen controls.

Expected evidence: Record the actual phone model, Android/browser versions, launch display mode, safe-area layout and release. Fullscreen may fall back where the OS/browser does not support it.

Android offline and process termination

Android phone · Not run

After a complete download, enable OS airplane mode. Force-stop the installed app and reopen from its icon. Start Adventure and Daily, move/launch/pause, watch a cutscene, resume a saved run, and reopen again. Restore networking.

Expected evidence: Offline game/music/cutscenes load; progress survives ordinary termination; online status and score sync recover. Use a disposable board for synthetic submission/queue testing; do not insert QA scores into the shared board.

Android two-release update and interruption

Android phone · Not run

Start from release A and a saved run. Keep a second A tab open. Publish B, check for updates and verify an active run is not interrupted. Apply from a safe screen. Repeat with a deliberately unavailable B asset on a local test host, then restore it and retry.

Expected evidence: Failed B leaves A usable. Successful B retains settings/checkpoint/outbox; the older tab keeps its A modules. Capture both release identities and visible update states.

Android storage pressure and recovery

Android phone · Not run

On a disposable installation, test a full/denied storage condition and separately remove a cached game asset using supported developer controls. Retry download online. Never clear the player’s primary installation or its saves.

Expected evidence: No false offline-ready claim. Failures explain recovery; available saves/outbox are retained where storage permits. Record actual OS eviction separately from simulated cache removal.

Android received Slack share

Android phone and Slack receiver · Not run

Share a Daily leaderboard entry through Android’s native sheet to a destination you explicitly choose. Inspect the received Slack message. Repeat with the scorecard option.

Expected evidence: Received text includes score, readable challenge date and link; received file is readable when supported. Record sender/receiver app versions and a redacted received-message screenshot; payload inspection alone is insufficient.

iOS installation and display

iPhone/iPad · Not run

Use a disposable Safari installation. Wait for offline readiness, Add to Home Screen, close Safari and launch from the icon. Check portrait/landscape, safe areas, dialogs and controls.

Expected evidence: Actual installed display mode and layout recorded. Do not claim Android-style fullscreen where iOS supplies standalone mode.

iOS offline and termination

iPhone/iPad · Not run

After complete download, enable OS airplane mode, terminate the app and reopen. Play, save/resume, hear music and finish a world. Restore connectivity.

Expected evidence: Complete offline game works and reconnects without losing available progress. Record actual device behavior, not desktop emulation.

iOS two-release updates

iPhone/iPad · Not run

Repeat the A-to-B safe-screen update, interrupted download, two-client and retry cases using Safari and the installed app.

Expected evidence: No forced update during play, coherent assets, retained state and actionable failure recovery.

iOS storage pressure

iPhone/iPad · Not run

Use a disposable installation to observe storage denial/eviction and recovery. Separate OS-initiated eviction from deliberate developer-tool removal.

Expected evidence: The app does not claim complete offline readiness when assets are missing; online recovery remains usable. Do not promise persistence against destructive OS eviction.

iOS received share

iPhone/iPad and chosen receiver · Not run

Share text/link and a scorecard through the native sheet to a destination you explicitly select. Inspect the received items.

Expected evidence: Readable score/date/link and supported file delivery; record actual receiver/version and redacted evidence.

Independent campaign balance

Independent human · Not run

Play all sixteen worlds with ordinary lives and no diagnostic completion shortcuts. Record lives, failure points and power-up usefulness.

Expected evidence: Reviewer reports completion/difficulty and actionable balance findings. A bot run is separate supporting evidence.

Independent cinematic and audio review

Independent human · Not run

Watch every world transition and Adventure/Daily/top-score ending, with normal and reduced motion. Listen on phone speaker/headphones at comfortable levels.

Expected evidence: Headings/bonuses remain readable for the available time; motion is tolerable; tracks, victory cues and effects are distinguishable without objectionable peaks.

Keyboard and large text

Independent human · Not run

Navigate start/settings/worlds/help/leaderboards/sharing with keyboard only; play/pause/resume; test 200% zoom and enlarged system text on a suitable device.

Expected evidence: Visible focus, sensible tab order, no trapped dialogs, reachable actions, no clipped essential copy. Record browser/device and issues.

Screen-reader speech

Independent human using a screen reader · Not run

Use a named screen reader/browser pair to navigate menus, dialogs, leaderboard and game status. Play where feasible and review pause/result recovery.

Expected evidence: Names and status changes make sense when spoken, updates do not overwhelm speech, modal focus returns correctly. This is a scoped review, not blanket accessibility certification.

Record exact release and source, reviewer, observed UTC time, environment, result and evidence using tools/acceptance-status.mjs. A submitted record is a human assertion, not an independent hardware attestation.
